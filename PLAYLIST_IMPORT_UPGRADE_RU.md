# SwiDJ: импорт плейлистов — 30 октября 2026

Добавлен импорт в обычный Telegram-бот и Mini App. Существующие поиск, скачивание, эффекты, DJ, видео и коллекции сохранены. Рабочая сборка: `swidj:playlist-import`, функциональный GitHub-коммит `1f3dfdd`. Выполнен один перезапуск основного бота в 17:45:23 UTC; отдельный видеосервис и браузер YouTube не перезапускались. Изменения схемы SQLite не требуются; предыдущий образ и compose сохранены для отката.

## Пользовательский сценарий

Ссылка → предпросмотр доступных песен → подтверждение → свой плейлист SwiDJ. Открытие песни вызывает существующий выбор аудиоверсий из доступных источников. Массового скачивания всех аудиофайлов при импорте нет. Метаданные подписочного каталога не означают скачивание защищённого оригинала. Выбранная запись готовится обычным загрузчиком с существующими проверками и резервами.

Mini App: **Моя музыка → Импорт плейлиста**. Бот: отправить ссылку, нажать импорт в разделе плейлистов или написать `/import` и список в одном сообщении. Формат списка: `Исполнитель — Название`, одна песня на строке; обычный дефис тоже подходит. Это ввод списка для музыкальной коллекции, а не выдача текстового файла.

Коллекция общая для бота и Mini App, сохраняется после перезагрузки и редактируется обычными действиями. Исходный внешний плейлист не меняется. Автосинхронизация не добавлялась. Повторный одинаковый импорт не создаёт дубликат и не перезаписывает пользовательские изменения.

## Каталоги

Проверены публичные списки YouTube / YouTube Music, SoundCloud, Spotify, Apple Music, Deezer, Bandcamp, Audius и Jamendo. Поддерживаются соответствующие плейлисты и/или альбомы; Bandcamp — альбомы, Jamendo — публичные списки. Содержимое может меняться на стороне сервиса. Если опубликован исходный счётчик, неполный результат обозначается количеством доступных позиций из общего числа. Например, контрольный Audius-плейлист отдал 4 доступные записи из 7.

Яндекс Музыка: адаптер публичных списков есть, но текущий VPS получает региональную/сетевую блокировку списка. Это не считается успешным импортом по ссылке. При этом прежние ссылки на отдельные песни прошли проверку. Для Яндекса, VK и любых других каталогов можно вставить известный пользователю список названий. По одному названию закрытого плейлиста его содержимое не угадывается и не подменяется случайными песнями.

TikTok и Instagram остаются источниками отдельных публикаций аудио/видео; музыкальный импорт плейлистов из них не заявлен. Spotify embed может раскрыть только публичную часть списка, поэтому полнота не обещается там, где сервис не сообщает общее число записей. Приватные плейлисты без доступа не импортируются. Гарантии наличия каждой аудиозаписи во внешних источниках нет.

## Сохранность и ограничения

До 500 записей на импорт, 30 коллекций на пользователя, до 50 000 символов текстового списка. Старые лимиты обычных коллекций/избранного не уменьшались; импортированные коллекции редактируются до 500 записей. Сохраняется только список и данные найденных/выбранных записей, без немедленного заполнения диска сотнями аудиофайлов.

API проверяет подпись Telegram, владельца предпросмотра, срок 30 минут и подтверждение. Доступ другого пользователя к токену импорта отклоняется. Запись использует общую блокировку пользователя и существующую атомарную транзакцию библиотеки. Чтение метаданных ограничено двумя задачами Mini App; повторные предпросмотры ограничены по частоте. Адреса принимаются по списку известных HTTPS-хостов и путей; нельзя передать локальный адрес сервера или произвольный URL пагинации.

Окно импорта, как и создание/переименование плейлиста, не закрывается от фоновой смены трека. Надписи добавлены на русском и английском; раздел «Возможности» дополнен одной короткой строкой. Обновлён Dockerfile для включения нового модуля и уже используемых модулей каталога/справки.

## Итог серверного прогона

Повторно проверены 15 наборов сценариев: ядро API, ссылки Mini App, чатовые загрузчики, независимые поиски, резервы аудио и видео, кэш, голосовой поиск, видео 1080p, видеостудия, синхротекст, бета-мелодия, дополнительные ссылки, восстановление навигации, каталоги исполнителей, карточка возможностей и новый импорт. Большинство наборов прошли с первого раза. Две проверки потребовали отдельного разбора:

- В первом каталожном прогоне не появился ожидаемый исполнитель MusicBrainz. Отдельный запрос затем вернул HTTP 200; повтор исходного сценария прошёл для трёх пользователей: по 195 релизов из Apple Music/MusicBrainz и по 20 треков открытого альбома, плюс навигация бота RU/EN. Точная причина первого отсутствующего результата не установлена; она не скрыта из журналов.
- Проверка автоматического синхротекста в видео не прошла, включая отдельный повтор. Диагностика установила HTTP 503 от внешнего LRCLIB при поиске контрольной записи; длительность аудио корректна — 213,072 с. Этот внешний сбой не объявляется исправленным. Обычный поиск текста в основном API прошёл, видео без автоматического синхротекста прошло. Функция сохранена, но постоянная доступность внешнего поставщика не гарантируется.

Резерв SoundCloud прошёл; резерв видео в чате и Mini App отдал MP4 с ограничением 720p. Проверены настоящие аудиофайлы, Range 206, YouTube 1080p размером 109 436 126 байт, 18 видеопресетов и рендер 1080p60 H.264/AAC. Голосовой поиск и контрольное AcoustID-распознавание прошли. Бета-распознавание мелодии не выдаётся за гарантированное распознавание любого напевания. Контрольные отпечатки реальных коллекций остались прежними.

Новый рабочий API импорта проверен без записи в реальные коллекции: YouTube — 1 запись; SoundCloud — 8; Spotify — 50; Apple Music — 100; Deezer — 50; Bandcamp — 8; Audius — 4 доступные из 7; Jamendo — 2. Запись/повторное открытие/общая библиотека проверены отдельно на временной SQLite в интеграционных и браузерных тестах. Это разделение не выдаётся за реальные Telegram-сообщения или аппаратную проверку телефона.

## Повторная проверка синхротекста после восстановления

В последующей отдельной проверке функция восстановилась без изменения кода или перезапуска: рабочий API вернул 59 синхронизированных строк для Rick Astley и 48 для Adele. Исходный сценарий `live-motion-check.py` затем успешно создал видео 1080p60 с 59 строками, плавающим текстом и анимацией, скачивание подтвердило Range 206. Некоторые прямые запросы LRCLIB одновременно продолжали возвращать HTTP 503; это частичная/периодическая недоступность поставщика, а не поломка всей функции. Для контрольного Imagine приложение не вернуло синхротекст в этой попытке; доступность любого отдельного трека не гарантируется. Сохранены первоначальные ошибки и журналы восстановления `timed-status.log`, `live-motion-recovered.log`.
